## Definition

Read–Write Reflective Learning is a memory-update loop for LLM agents that casts external memory operations as policy iteration. **Reading** corresponds to policy improvement: a retrieval policy selects the most useful memory item (a skill, a case, a procedure) to condition the LLM's next action. **Writing** corresponds to joint policy evaluation and improvement: the system records the execution outcome and a diagnostic trace, then mutates the underlying memory artefact based on those signals. Because the artefact directly determines the next action, every write step is a concrete policy update — no LLM weights are touched.

The loop has five canonical phases: **Observe → Read → Act → Feedback → Write**. Convergence is inherited from the Reflected MDP construction of the Stateful Reflective Decision Process: KL-regularised soft policy iteration over the augmented state $x_t = (s_t, \mathcal{M}_t)$ converges to the optimal retrieval policy under bounded rewards and $\gamma < 1$.

## Intuition

The classical fine-tuning loop updates $\theta$ via gradient descent on a labelled dataset; the agent gets "smarter" because its weights change. Read–Write Reflective Learning freezes $\theta$ and instead updates the *input* the model sees — but it does so structurally, not just by extending a context buffer. The memory itself is the policy, and the write operator is what makes the policy improve.

Two design choices distinguish it from a vector store with append semantics:

- **Writes are mutations, not appends.** A failed execution does not just log a trace; it rewrites the responsible skill artefact (its prompt, its code, its `SKILL.md` spec) so the next read returns an improved policy.
- **Reads use behavioural utility, not lexical similarity.** Retrieval is trained to optimise execution success, not surface match — otherwise the loop converges on cosmetically similar but operationally wrong skills.

## Variants

- **Trace-level reflective memory** (Memento, Reflexion): writes append episodic case traces; reads retrieve the closest case to seed the LLM's next decision.
- **Tip-memory + skill-level reflective learning** (Memento-Skills): writes split into (a) generic tip memory updates and (b) skill-level rewrites driven by a failure-attribution selector; reads condition on both an augmented input $(q_t, \mathcal{T}_t)$ and the selected skill folder.
- **Prompt-only reflective rewriting** (GEPA-Skill, Letta Skill Learning): writes edit a text-only skill guide; no executable scripts, no unit-test gate.

## Comparison

| Axis | Read–Write Reflective Learning | Supervised fine-tuning | Online RL (PPO/REINFORCE) |
|---|---|---|---|
| What changes | external memory artefact $\mathcal{M}$ | LLM parameters $\theta$ | LLM parameters $\theta$ |
| Update signal | judge verdict + trace | labelled (input, target) | scalar reward |
| Cost per update | small (rewrite a file) | large (gradient step on $\theta$) | large + on-policy rollout |
| Persistence | survives across LLM versions | tied to $\theta$ | tied to $\theta$ |
| Convergence guarantee | KL-regularised soft policy iteration (Memento~2 Thm 8) | none in general | depends on assumptions |

## Known limitations

- The unit-test gate is only as good as the synthetic tests generated by the judge — silent regressions can still slip through.
- Performance depends on a high-quality failure-attribution selector; mis-attribution sends the rewriter at the wrong skill.
- Triggering condition is episode-bounded; trajectory-level / long-context reflection has no canonical formulation yet.

## Open problems

- **Multi-agent concurrent writes.** Race conditions when multiple agents try to rewrite the same skill artefact remain unsolved.
- **Continuous-time reflection.** Without discrete episode boundaries, when does an agent pause to write?
- **Retirement.** When utility drops persistently, should the system rewrite, deprecate, or delete? No principled policy exists.

## Relationship to foundations

The mathematical core is policy iteration over the Reflected MDP — soft policy iteration with a KL-regularised objective. The "convergence guarantees" come from this classical RL substrate. The novelty is not in the iteration scheme but in the choice of memory unit (skill folder vs episodic trace vs text guide) and the write operator (mutating files vs appending records).

## My understanding

The framing's strength is making each write a concrete, inspectable artefact change rather than a hidden weight perturbation. This buys debuggability (you can `diff` a skill before and after), rollback (the unit-test gate), and portability across LLM backbones (the skill folder is the policy, not $\theta$). The framing's weakness is that *how well* the write operator improves the policy depends entirely on the quality of two LLM-internal modules — the failure-attribution selector and the skill rewriter — neither of which has a guarantee. The convergence proof says the *retrieval* policy converges; it does not say the rewriter's edits are correct.
